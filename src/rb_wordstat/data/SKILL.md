# wordstat

Всё про конкретные команды есть в самом CLI: `wordstat` без аргументов —
версия и список команд, `wordstat <команда> --help` — подробности и примеры.
Этот документ — только то, чего `--help` не скажет. Если CLI запускать
можно, а файлы читать нельзя, этот же текст печатает `wordstat --ai`.

## Правила

- **`--json` у каждой команды.** Разбирать stdout; человеческий вывод не
  парсить. В stdout — только данные, в stderr — диагностика.
- **Провайдеры — очередь.** `--provider a,b` (или `providers` в настройках
  проекта): отвечает первый, остальные — фолбэки по порядку, только если
  предыдущий упал. По умолчанию `xmlriver`. Кто ответил — поле `provider` у
  каждого результата.
- **Запросы платные** — каждая пара (запрос, тип частоты) стоит один запрос
  к провайдеру. `--freq all` на 10 запросов — это 40 платных запросов.
  Брать только нужные типы частоты.
- **Каждый ответ сохраняется в журнал.** Повторный запрос, если свежесть не
  критична, — с `--cache` (бесплатно; `--max-age 7d` при необходимости).
  Журнал ведётся по провайдерам: из журнала берутся только ответы
  провайдеров из `--provider`. В результате видно `from_cache` и
  `fetched_at`. `--force` — только если пользователь просит свежие данные.
  Журнал — `wordstat cache info|list|clear`.
- **Данные** — в общей PostgreSQL, если задан `WORDSTAT_DATABASE_URL`
  (иначе локальный SQLite). `DATABASE_UNAVAILABLE` (код 5) — сервер
  недоступен, ничего никуда не записано; `DATABASE_NOT_MIGRATED` →
  `wordstat db upgrade` (меняет общую базу — сначала спросить
  пользователя); ревизия — `db status --json`. `db push --dry-run`, затем
  `db push` — отправить локальные ответы в прод
  (`WORDSTAT_PROD_DATABASE_URL`; уже имеющиеся пропускаются). Запускает
  только корневой агент tools; любой другой агент присылает ему точную
  команду. Читать
  данные wordstat из SQL — только через представления `wordstat_v1_*`.
- **Частота 0 — не сбой**, а «запрос не ищут». Сбой провайдера всегда
  даёт код выхода 3 или 5, а не нули.
- **Проект необязателен.** Без него работают настройки по умолчанию;
  `wordstat init --non-interactive` создаёт `.wordstat/config.toml`, чтобы
  закрепить очередь провайдеров за папкой.
- **`--non-interactive`** для всего, что может задать вопрос: вместо
  зависания будет понятная ошибка.
- **Доступы** общие с CLI `serp`: keychain / env `WORDSTAT_<PROVIDER>_<FIELD>`,
  иначе записи serp (`SERP_<PROVIDER>_<FIELD>`, keychain `serp:<provider>`),
  никогда не в аргументах или настройках. Проверка —
  `wordstat auth status --check --json`: по каждому провайдеру источник,
  статус, срок и остаток — без значений; код 3, если обязательный xmlriver не
  в порядке. Вход — `wordstat auth login`
  (или `serp auth login`). Никогда не просить пользователя вставить секрет в
  командную строку.
- **Необратимые команды** — те, у которых в `--help` есть `--dry-run` и
  `--confirm` (сейчас это `cache clear`). Всегда: сначала `--dry-run`,
  показать пользователю, получить явное согласие, потом
  `--confirm --non-interactive`.
- **Сначала `wordstat doctor --json`**, если что-то не так: он проверяет
  проект, настройки, совместимость версий и доступы.
- **`wordstat describe --json`** — весь CLI одним машиночитаемым документом
  OpenCLI (команды, опции, коды выхода, переменные окружения, данные):
  документ как есть, без обёртки `{"ok": ...}`.

## Ошибки

Ошибка: `{"ok": false, "error": {"code", "message", "action"}}`.
Порядок: код выхода → `error.code` → `error.action` (конкретная команда,
которая исправит).

    0  успех
    1  прочее (UNEXPECTED — баг: повторить с --verbose и сообщить; ABORTED — пользователь отказался)
    2  неверные аргументы
    3  нужны доступы              → wordstat auth login --provider <имя>
    4  проект не создан           → wordstat init
    5  сбой провайдера (сеть, деньги на счёте, лимиты; повторы уже были) → позже или другой провайдер
    6  CLI старее, чем нужно проекту → uv tool upgrade rb-wordstat

Автоматически повторять имеет смысл только код 5.
